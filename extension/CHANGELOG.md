# 更新日誌

## v0.5.0 — Google Drive(2026-09-18)

**白話說明**:在 Google Drive 或 Google 文件看到 .md 時,右下角會出現「📖 用 MD隨手讀 開啟」,按下去就用 MD隨手讀 排版。Google 自己的預覽已經能顯示一般 Markdown,這顆按鈕主要是給 Obsidian 筆記用的(提示框、雙中括號連結、屬性表、流程圖、公式 Google 都看不懂)。

### 新增
- **Drive 按鈕**:三個地方會出現 —— 檔案預覽頁、Google 文件的 Markdown 模式、Drive 列表裡選取了一個 .md 時
- 讀不到檔案(沒登入、沒權限)時,清楚說明原因,並建議改用 Drive 的「下載」(下載完 MD隨手讀 會跳通知幫你打開)
- 小視窗「最近開過」會把 Drive 的檔案標成 ☁️ Drive
- 設定頁「閱讀」新增:Google Drive 按鈕(開關)
- 閱讀頁開網路檔時,改用伺服器給的真正檔名當標題;打開的網址如果其實是一般網頁,會說明「不是 Markdown 檔」,不會把網頁原始碼當文件排版

### 修正
- (無)

### 影響範圍
- 移除第 0 期的「🧪 Drive 診斷」按鈕
- Google 文件(docs.google.com/document)頁面也會載入 MD隨手讀 的小程式(只在標題是 .md 時顯示按鈕)

### 技術細節
- 新增 `content/drive.js`:每秒檢查目前檔案(Drive 是單頁應用程式,網址與畫面會原地變);檔案編號取自網址 `/file/d/<ID>`、`/document/d/<ID>`,或列表中 `[data-id][aria-selected="true"]`
- 原文用 `https://drive.google.com/uc?export=download&id=<ID>` 取得(會 303 轉到 drive.usercontent.google.com 並附檔名),由閱讀頁帶登入 Cookie 讀取 —— 已用公開檔實測確認轉址與檔名
- 真實 Drive 頁面需要登入,自動化測試用模擬頁面測判斷邏輯;登入後的實際效果列在人工驗收

## v0.4.0 — 看得懂 Obsidian 筆記、流程圖、數學公式(2026-09-18)

**白話說明**:Obsidian 筆記現在能漂亮顯示了:開頭的屬性變成屬性表、`[[雙中括號連結]]` 可以點、`> [!tip]` 變成彩色提示框,還有螢光筆、標籤、腳註、嵌入圖片。另外流程圖(Mermaid)和數學公式也會直接畫出來。
(原本規劃的 Google Drive 版順延為 v0.5,等 Drive 診斷結果)

### 新增
- **屬性表**:筆記開頭 `---` 包起來的屬性顯示成表格;清單變成標籤膠囊、勾選變成方框、網址和 `[[連結]]` 可以點。可在設定頁關掉
- **雙中括號連結** `[[筆記]]`、`[[筆記|顯示文字]]`、`[[筆記#段落]]`、`[[#段落]]`、`[[#^區塊]]`
  - 預設:找同一個資料夾裡的同名 .md
  - 設定頁填了「Obsidian 保險庫名稱」:直接在 Obsidian App 打開那篇筆記(不管放在哪個資料夾)
- **提示框**:note、tip、warning、danger 等 13 種類型與別名,顏色、圖示同 Obsidian;支援 `[!tip]-` 預設收起、`[!tip]+` 可收起、提示框裡再包提示框
- **螢光筆** `==重點==`、**標籤** `#標籤`(程式碼與網址裡的不算)、**腳註** `[^1]`
- **隱藏註解** `%%看不到%%`、**區塊 ID** `^abc` 不顯示,且能被 `[[#^abc]]` 連過去
- **嵌入** `![[圖.png]]`、`![[圖.png|300]]`:自動到附近的 `_attachments`、`attachments`、`assets`、`images` 資料夾找圖;`![[筆記]]` 顯示成可點的嵌入框
- **Mermaid 流程圖**:流程圖、循序圖等;跟著深淺色換配色;語法錯誤時顯示說明,不會整頁壞掉
- **數學公式**:`$行內$`、`$$區塊$$`(KaTeX);「$5、$10」這種價錢不會被誤判
- 設定頁「閱讀」新增:顯示屬性表(開關)、Obsidian 保險庫名稱

### 修正
- 沒有 `# 標題` 的筆記,分頁標題改用屬性裡的 `title`

### 影響範圍
- 所有排版畫面都會套用新語法;一般 Markdown 文件不受影響
- 有流程圖的文件第一次打開會稍微慢一點(載入 3.5MB 的流程圖元件),沒有流程圖的文件不會載入

### 技術細節
- 新增 `core/syntax.js`(markdown-it 外掛:wikilink、embed、math;前處理:註解、frontmatter)、`core/obsidian.js`(消毒後加工:callout、tag、block id、連結網址、嵌入圖片、屬性表)、`core/diagram.js`(Mermaid 延遲載入)
- 新增元件:markdown-it-mark 4.0.0、markdown-it-footnote 4.0.0、js-yaml 4.3.2(CORE_SCHEMA,日期維持文字)、KaTeX 0.18.7、Mermaid 11.17.2
- `[[連結]]` 在解析時只寫 `data-href`,消毒後才依設定填網址(DOMPurify 會擋 `obsidian://`)
- Mermaid 在一般網頁由背景管家用 `chrome.scripting` 注入(新增權限 `scripting`,只允許注入白名單檔案);SVG 輸出也經過 DOMPurify
- KaTeX 字型網址改成 `chrome-extension://__MSG_@@extension_id__/…`(content script 的 CSS 相對路徑會對到網頁),字型列為 web_accessible_resources

## v0.3.0 — 右鍵開啟、小視窗、最近開過(2026-09-18)

**白話說明**:現在點工具列上的 MD隨手讀 圖示,會跳出一個小視窗:可以開電腦裡的檔案、貼上 Markdown 文字或網址、看最近開過的文件。網頁上看到 .md 連結,按右鍵就能直接用閱讀器打開。

### 新增
- **右鍵「用 MD隨手讀 開啟」**:任何 .md 連結按右鍵都有這個選項,在旁邊開新分頁排版。GitHub、GitLab 的檔案頁連結會自動換成原始檔,連強制下載或沒副檔名的網址也能開
- **工具列小視窗**(點 MD隨手讀 圖示)
  - 📂 開啟電腦裡的 .md(開一個「選擇檔案」分頁)
  - 📋 貼上框:貼一段 Markdown 文字 → 排版;貼一個網址 → 打開那個網址(⌘ + Enter 也能送出)
  - 🕘 最近開過的 8 份文件,標出本機 / 網路 / 貼上,點了就重新打開
  - 還沒開檔案權限時,最上面會提醒並帶你去開
  - 下方 ⚙️ 設定、📜 更新日誌
- **開啟檔案頁**:選一個 .md 就排版;也提醒你「直接拖進分頁」效果更好(圖片也能顯示)
- **設定頁「閱讀」新增**:記錄最近開過的檔案(開關)、清除最近紀錄

### 修正
- (無)

### 影響範圍
- 點工具列圖示從「直接開設定頁」改成「跳出小視窗」;設定頁改從小視窗下方的 ⚙️ 進入(閱讀畫面右上角的 ⚙️、擴充功能選項也照舊可用)
- 開過的 .md 會被記錄在這台電腦(可在設定頁關閉或清除)

### 技術細節
- 新增 `core/library.js`(最近清單、貼上文字暫存,存 chrome.storage.local,各保留 10 筆)、`pages/popup.*`、`pages/open.*`
- 右鍵選單用 `chrome.contextMenus`,只在 .md 連結出現(`targetUrlPatterns`);一律走閱讀頁 `viewer.html?src=`
- 閱讀頁新增 `?doc=` 讀取文件庫;抓網路檔改為帶 Cookie(私人網址也讀得到)
- 小視窗不放拖放區與選檔:小視窗一失去焦點就會關閉,從 Finder 拖檔案或打開選檔視窗都會讓它先關掉
- 新增權限:`contextMenus`

## v0.2.0 — 正式閱讀畫面、設定頁、更新日誌(2026-09-18)

**白話說明**:排版畫面升級成真正好讀的樣子(左邊目錄、程式碼有顏色、待辦清單有勾選框),右上角多了一排小按鈕;另外有了「設定頁」,所有可以調的東西都集中在這裡,更新日誌也能直接在插件裡看(就是你現在看的這一頁)。

### 新增
- **左側目錄**:列出文件所有標題,點了就跳過去,捲動時會標出目前讀到哪一段;螢幕窄的時候自動收起來
- **右上角工具列**:☰ 目錄開關、◐ 主題切換(跟隨系統 → 淺色 → 深色)、〈/〉 看原始碼、⚙️ 打開設定
- **程式碼上色**:JavaScript、Python、Shell、JSON、HTML、CSS、SQL 等常見語言
- **待辦勾選框**:`- [ ]`、`- [x]` 顯示成方框,已完成的會淡化加刪除線
- **設定頁**:外觀(主題、字級、版面寬度,附即時預覽)、閱讀(目錄)、下載(跳通知 / 自動開 / 不處理)、檔案權限狀態、更新日誌
- **三個地方都能打開設定**:閱讀畫面右上角 ⚙️、點瀏覽器工具列上的插件圖示、Chrome 擴充功能頁的「擴充功能選項」
- **設定跨電腦同步**:登入同一個 Google 帳號時,Mac 和 Windows 的設定會自動同步
- 改了設定,已經開著的閱讀分頁會**立刻跟著變**,不用重新整理
- 列印 / 存成 PDF 時自動隱藏目錄與工具列,只印內文

### 修正
- 引用區塊底部多出一段空白

### 影響範圍
- 所有排版畫面(本機、網路、下載、閱讀頁)外觀都換新
- 下載行為改由設定決定(預設仍是「跳通知,點了才開」,跟 v0.1.0 一樣)

### 技術細節
- 新增 `core/settings.js`(設定,存 chrome.storage.sync)、`core/reader.js`(閱讀畫面外殼)、`pages/options.*`(設定頁)
- 新增 highlight.js 11.12.0;任務勾選框與標題錨點在消毒之後才加(不經過 innerHTML)

- 自動化測試改名 `npm test`

## v0.1.0 — 第 0 期技術驗證(2026-09-18)

**白話說明**:先做一個「最小但真的能用」的插件,用來確認四個入口會不會卡關。結果:本機、網路、下載三條路在自動化測試裡全部走通,Google Drive 需要你登入後實測。

### 新增
- 本機 .md 檔用 Chrome 打開時,自動換成排版好的閱讀畫面(中文、表格、程式碼、引用)
- 網路上的 .md 網址自動排版,包含:沒宣告編碼的(中文不亂碼)、網站強制下載的(改成直接顯示)、有嚴格安全設定的(像 GitHub raw)
- 下載完 .md 檔會跳通知,點通知就用新分頁打開並排版
- 第一次安裝時,如果還沒開「允許存取檔案網址」,自動打開繁中圖解引導頁,開好會即時變綠色
- 閱讀頁(給 Drive、Windows 等不能就地排版的情況用)
- 安全消毒:MD 檔裡夾帶的惡意程式碼一律擋掉
- Google Drive 診斷按鈕(暫時的,實驗用)
- 插件圖示

### 修正
- (第一版,無)

### 影響範圍
- 新專案,無既有功能受影響
- 插件會在所有 .md 網址載入;本來就是網頁的 .md(例如 GitHub 的檔案頁)不會被動到

### 技術細節
- Manifest V3,最低 Chrome 128;markdown-it 14.3.2 + DOMPurify 3.4.15,放在 `extension/vendor/`
- 網路規則(declarativeNetRequest):`.md` 網址且回應帶 `content-disposition: attachment` → 移除;回應沒宣告編碼且不是 HTML → 改成 `text/plain; charset=utf-8`
- 下載:`chrome.downloads.onChanged` 完成 → `chrome.notifications` → 點擊後 `chrome.tabs.create(file://…)`(Chrome 118+ 需檔案存取權限,沒有時改開引導頁)
- 閱讀頁讀本機檔用 XMLHttpRequest(fetch 不支援 file://)
- 自動化實驗:`npm run test:poc`,14/14 通過(Chrome for Testing 153)
