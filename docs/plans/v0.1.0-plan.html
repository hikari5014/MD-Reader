0一句話結論

技術上完全做得到。市面上已經有好用的閱讀插件,但沒有一個能「全方位」一次搞定:Google Drive 要另裝一個、下載的檔案不會自動打開、看不懂 Obsidian 的特殊語法、介面幾乎都是英文。

👉 我的建議:從零做一個輕量、繁中、所有入口共用同一個閱讀畫面的插件,分 6 期交付、每期都能實際用,約 2 週完成自用版。

1大神們怎麼做?(市場調查)

我查了目前 Chrome 商店最多人用的幾款,整理「它們做得好的」與「缺口」。

插件使用人數做得好的缺口開源?
Markdown Viewer
(simov)		約 40 萬外掛最多、30+ 種主題、流程圖、數學式、自動重新整理介面老舊複雜;2024-05 後沒更新;不支援 Drive✅ MIT
Markdown Reader
(md-reader)		約 10 萬介面精緻、側邊目錄、持續維護新版閉源;資料夾瀏覽要付費❌(僅舊版)
MarkView成長中資料夾瀏覽、目錄跟隨捲動、圖片燈箱、15 種介面語言閉源;不支援 Drive❌
Skim新免費開源、有「開權限」引導、輕量很新、實戰測試少✅ MIT
Google Drive Markdown Preview小眾專門讓 Drive 預覽 .md 時變漂亮只管 Drive,要另外裝✅

🧠 大神們的共通做法(我們直接借鏡)

① 本機檔:把純文字「就地換裝」

Chrome 打開 .md 本來只會顯示一坨純文字。插件在頁面裡放一個小程式,把純文字讀出來、換成排版好的畫面。關鍵卡關點:Chrome 規定使用者必須自己手動打開「允許存取檔案網址」開關,插件沒辦法代開 → 所以要做一頁清楚的繁中引導。

② 網路檔:兩招辨識

看網址結尾是不是 .md / .markdown,或看伺服器宣告的檔案類型是不是純文字或 markdown。兩者任一符合就排版。

③ Google Drive:在 Drive 頁面加按鈕

在 drive.google.com 放小程式,偵測你正在預覽 .md,就把原文拿去排版。缺點是 Drive 頁面是 Google 的,Google 一改版可能就要修。

④ 下載檔:幾乎沒人處理 → 我們的特色

兩招:(a) 伺服器說「這是附件請下載」時,把這句話拿掉,讓它直接顯示;(b) 下載完成後,插件自動在新分頁打開那個檔案。

⑤ 安全:一定要「消毒」

MD 檔裡可以偷偷夾帶網頁程式碼。如果直接顯示,惡意檔案可能做壞事。所以每份文件顯示前都要先過消毒器。這是大神們都有做、我們也絕對要做的底線。

🎯 我們的差異化(別人沒有、你需要的)
🧩 五個入口、同一個閱讀畫面 🇹🇼 全繁中介面 🔗 看得懂 Obsidian 語法(你的知識庫就是 Obsidian) ⬇️ 下載的 .md 自動打開 ☁️ Drive 內建,不用另裝 🖱️ 任何 .md 連結右鍵直接看

2三種做法並排比較

點一張卡片可以在右邊的雷達圖上突顯它。分數越外圈越好。

做法 A
直接用現成的
Markdown Viewer + Drive 預覽插件
開發:0 天
  • 👍 馬上能用、免費
  • 👎 兩個插件兩套外觀
  • 👎 下載檔不處理
  • 👎 看不懂 Obsidian 語法
  • 👎 英文介面、不能照你的意思改
適合:只想「看得懂」就好
做法 B
改造開源大神版
拿 simov 的 Markdown Viewer 來改
開發:約 7 天
  • 👍 成熟功能直接繼承
  • 👍 開源授權可自由改
  • 👎 程式碼龐大、2024 後沒更新
  • 👎 設定頁複雜,改一處動全身
  • 👎 很多用不到的功能要一起維護
適合:想要超多進階功能
⭐ 推薦
做法 C
從零打造輕量版
借鏡大神做法、只做你要的
開發:約 10 個工作天(分 6 期)
  • 👍 五個入口同一個畫面
  • 👍 繁中、Obsidian 語法
  • 👍 程式小,日後好改
  • 👍 每一期都能先用
  • 👎 Drive 部分需隨 Google 改版維修
適合:要「一個插件搞定全部」並長期自用
💡 老實話(極簡原則):如果你只是偶爾看一下 .md,做法 A 今天就能解決 80% 的需求。我推薦 C 的理由是:①你要「全方位」,現成的得裝 2 個還補不齊下載;②你的中央知識庫是 Obsidian 繁中筆記,現成的看不懂 [[雙中括號連結]] 和提示框。
👉 小建議:開發前先裝 A 玩 10 分鐘,當作「好用的標準」,之後驗收我們的版本時比較有感。

3整體架構圖

核心概念:五個入口 → 同一顆排版引擎 → 同一個閱讀畫面。入口再多,排版只做一次,所以好維護、外觀一致。

藍=入口 紫=排版引擎 綠=閱讀介面 黃=設定與記憶

4使用者流程圖 + 風險預警

包含「失敗」與「取消」的路線。紅色閃爍的是風險點,滑鼠移上去看說明。灰色是失敗後的退路。

⚠️ 風險清單與對策

風險嚴重度對策
使用者不知道要開「檔案存取權限」高偵測到沒權限時,自動跳出繁中圖解引導頁(3 步驟)
Google 改版,Drive 按鈕消失高Drive 功能獨立成一塊,壞了不影響其他入口;失敗時提示改用下載或 Drive 電腦版
MD 檔夾帶惡意程式碼高所有內容一律過 DOMPurify 消毒;測試時放「惡意範例檔」驗證
網站強制下載,攔不到中雙保險:能攔就攔;攔不到就「下載完自動開」
圖表/數學元件太肥,拖慢速度中文件裡真的有圖表/公式時才載入(延遲載入)
Chrome 商店審核被退件低先自用不上架;要上架時權限只要最少、附隱私權政策

        ▶ 📘 名詞白話翻譯
        
    
          
    Chrome 擴充功能 / 插件:裝在 Chrome 裡的小程式,能改變網頁或增加功能。
    
          
    Manifest V3:Chrome 插件目前的規格版本,像插件的「身分證格式」。規定插件不能從網路下載程式來執行,所有元件都要打包在插件裡。
    
          
    file:// 網址:電腦本機檔案在瀏覽器裡的網址,例如 file:///Users/你/筆記.md。
    
          
    允許存取檔案網址:Chrome 的安全開關,開了插件才能讀本機檔案。只能使用者手動開。
    
          
    Content Script(頁面小程式):插件放進某個網頁裡執行的程式,能讀寫那一頁。
    
          
    背景管家(Service Worker):插件在背景待命的部分,負責監聽下載、右鍵選單等事件。
    
          
    markdown-it:把 MD 文字轉成網頁的「轉換器」,業界常用、可加外掛。
    
          
    DOMPurify:把危險程式碼剔除的「消毒器」。
    
          
    Mermaid:用文字描述就能畫出流程圖的工具(本頁的圖就是它畫的)。
    
          
    KaTeX:把數學公式漂亮顯示的工具。
    
          
    載入未封裝項目:不上架商店、直接把資料夾載入 Chrome 自己用的方式(開發者模式)。
    
          
    SemVer 版本號:主.次.修,例如 v0.2.0。v0.x 是開發中,v1.0.0 是正式可用。
    
        
    
      
    

      
    
        ▶ 🛠️ 工程備註(給工程師/未來的我)
        
      
          
    • 零建置原則:原生 JavaScript,第三方元件直接放 vendor/(壓縮版),不需要安裝 Node.js 或打包工具 → 你不用學任何開發環境。
      • 
          
    • 元件:markdown-it(+ task-lists / footnote / anchor 外掛)、自寫 Obsidian 規則(wikilink、callout、frontmatter,約百行內)、highlight.js、DOMPurify;Mermaid、KaTeX 只在文件需要時才載入。
      • 
          
    • 渲染兩種模式:本機/網路 → 在原頁就地排版(網址不變,可自動重新整理);Drive/手動/貼上 → 開插件自己的 viewer.html。兩者共用 core/。
      • 
          
    • 下載:declarativeNetRequest 移除 .md 網址的 Content-Disposition: attachment;另以 chrome.downloads.onChanged 在完成時開 file:// 分頁(Chrome 118+ 需使用者開了檔案存取權限)。
      • 
          
    • Drive:content script 偵測預覽中的 .md → 以使用者登入狀態抓取檔案內容 → 交給 viewer。先在第 0 期 PoC 驗證可抓取的方式,避免用 OAuth(要 Google 審核、太重)。
      • 
          
    • 權限最小化:file:///*、常見 raw 網域與 drive.google.com;「所有網站」改為使用者需要時再授權(optional host permissions)。
      • 
          
    • 安全:viewer 頁有插件權限,必須先消毒再顯示;設定嚴格 CSP;外部連結一律 rel="noopener"。
